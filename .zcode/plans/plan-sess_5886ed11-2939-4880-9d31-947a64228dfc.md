# Plan — Brancher le moteur mort + Compléter le Premier WOW (§41 CDC)

Principe directeur appliqué : « Scale When Required » — on branche ce qui existe déjà avant de construire du neuf. Chaque lot = code + tests + suite 1051+ verte + commit. Aucune dépendance nouvelle (pas de PostgreSQL/Redis dans ce périmètre).

Injecter les services réels à la place des `undefined` dans `AgentRuntimeService`/`ConversationIntelligenceService` : `CodeIntelligenceService`, `DNAService`, `ContextService`, `SemanticGraphService`, `ImpactService`, `MutationService` (tous existent, testés unitairement, jamais instanciés en prod).

## Lot 3 — Real Render + DNA réel + Compass 9 états
**Fichiers : `apps/studio/index.html`, nouveau `GET /api/v1/projects/:id/dna`, `routes/conversation.ts`**
1. **Bouton « Rendu réel (Chromium) »** dans le panneau preview → `POST .../render/preview` → affichage capture + erreurs console dans une modale. Première exécution réelle de `real-renderer.ts` (qui s'autodéclare non testé) ; chemin gracieux 503 si Chromium absent.
2. **Nouvelle route `GET /api/v1/projects/:id/dna`** : extraction DNA réelle via `DNAService` (Lot 1) → le panneau DNA affiche le manifeste EXTRAIT au lieu du JSON en dur.
3. **Compass complet** : la route `/stream` émet `sendSSE({type:'compass', state})` pour les 9 états (UNDERSTANDING au départ → PLANNING → EXECUTING par section → VALIDATING à la sauvegarde → COMPLETED) ; le client les mappe à `setCompassState`.
**Tests** : test route render (200 ou 503 gracieux) ; test route DNA ; garde-fou lot10 (9 états compass) ; repro live (1 création réelle).

## Lot 4 — Plan First : cartes de plan réelles dans le chat
**Fichiers : `routes/conversation.ts`, `apps/studio/index.html`**
1. La route `/stream` émet en début de réponse un événement `{type:'plan', plan}` construit par le Plan Engine existant (objectifs, étapes, fichiers impactés) — la carte s'affiche dans le chat pendant la génération (traçabilité §17, sans casser l'effet wow).
2. **Mode Plan First (toggle utilisateur, off par défaut)** : avec `planFirst:true`, le stream s'arrête après le plan (`done`, `awaitingConfirmation:true`) → la carte propose **Approuver / Modifier / Rejeter** (le handler orphelin `confirmConversationPlan` devient réel) → l'approbation relance le stream avec le plan confirmé.
3. Nettoyer les vestiges orphelins (`executePlanAction` sans call site).
**Tests** : test API (événement plan présent, mode planFirst s'arrête avant génération — sans LLM réel) ; garde-fous lot10 ; repro live.

## Lot 5 — Critique visuelle, Comparaison, Quality Gate
**Fichiers : nouveau `POST /api/v1/projects/:id/visual/analyze`, `apps/studio/index.html`**
1. **Route critique** : real render (capture + erreurs console) + analyse `visual-intelligence` (layout, hiérarchie, spacing, responsive) → rapport de findings structuré (le Design Critic v1 du CDC V8, alimenté par les moteurs existants).
2. **Comparer** : conservation du HTML avant modification ; bouton « Comparer » → A/B iframe + screenshots côte à côte + delta de score audit.
3. **Quality Gate** : après chaque génération/modification, audit automatique → bandeau score + erreurs page réelles ; si score < seuil ou erreurs runtime → bouton « Réparer via le chat » (message pré-rempli). La boucle Self-Repair complète (repair-orchestrator) reste hors périmètre.
**Tests** : test route visual/analyze (gracieux sans Chromium) ; garde-fous lot10 ; repro live final (création → modification → critique → gate).

## Garde-fous transverses
- Suite complète **1051+ tests verte** à chaque lot ; typecheck `tsc --noEmit` à chaque commit.
- Aucun `Math.random()` dans les scores (exigence CDC) — fallbacks déterministes conservés.
- Branche `feature/brancher-moteur-premier-wow`, un commit par lot, merge master en fin.
- Coût LLM : max 3-4 appels réels pour les repros live (générations minimales).
- Hors périmètre (explicitement) : PostgreSQL/Redis, auth utilisateurs, billing, WebSocket, i18n — Phase 0/5 du CDC pour plus tard.
